# Дослідження механізму захисту прошивки ESP32-C3 (Krutko VRX)

## Що видно з виводу esptool

```
Erase size 0, blocks 0, block size 0x4000, offset 0x0000, encrypt
Done!
```

Рядок **`encrypt`** наприкінці — ключова ознака. Він означає, що esptool виявив
увімкнене **апаратне шифрування флеш-пам'яті** (Flash Encryption) і записав
бінарник у вже зашифрованому вигляді.

---

## Механізм захисту ESP32-C3: Flash Encryption

### Як це працює

1. **Генерація ключа при першому завантаженні**
   - При першому старті (або при спеціальному прошиванні) ESP32-C3 генерує
     256-бітний AES-ключ (`FLASH_ENCRYPTION_KEY`) і записує його в **eFuse** —
     одноразово програмовану пам'ять.
   - Ключ позначається як **не для зчитування** (read-protected eFuse block).
   - Після цього eFuse `DIS_DOWNLOAD_MODE` та `DIS_ICACHE` можуть бути заблоковані.

2. **Шифрування при записі**
   - Весь вміст флеш-пам'яті зберігається у зашифрованому вигляді (AES-XTS-256).
   - Ключ шифрування **прив'язаний до конкретного чипа** — він унікальний.

3. **Прозоре дешифрування при виконанні**
   - Вбудований апаратний блок ESP32-C3 (MMU + Cache) розшифровує дані
     «на льоту» при зверненні CPU до флеш-пам'яті.
   - Програмний код ніколи не бачить зашифровані байти — лише CPU cache.

### Чому прошивку неможливо скопіювати

| Дія | Результат |
|-----|-----------|
| Зчитати флеш через esptool (`read_flash`) | Отримаєш **зашифровані** дані |
| Записати зчитане на інший чип | Прошивка **не запуститься** (інший ключ) |
| Спробувати зчитати eFuse-ключ | **Неможливо** — eFuse заблокований |
| Підключити JTAG/debug | Заблоковано через `DIS_USB_JTAG` / `HARD_DIS_JTAG` eFuse |

## Secure Boot v2 (другий рівень захисту)

Якщо увімкнено також **Secure Boot**:

1. Бутлоадер підписаний RSA-3072 або ECDSA-P256 ключем розробника.
2. Публічний ключ зберігається в eFuse (digest).
3. При кожному старті чип перевіряє підпис бутлоадера і образу додатка.
4. Якщо підпис не збігається — завантаження блокується.

Це означає, що навіть якби хтось зміг розшифрувати прошивку,
**модифікувати і запустити** її на тому ж пристрої неможливо без приватного ключа.

## Схема рівнів захисту Krutko VRX

```
┌─────────────────────────────────────────────────┐
│                  ESP32-C3 Chip                  │
│                                                 │
│  ┌──────────────┐     ┌────────────────────┐   │
│  │  eFuse Block │     │  Flash Memory      │   │
│  │              │     │  (encrypted AES-   │   │
│  │  AES-256 Key │────▶│   XTS-256)         │   │
│  │  (read-lock) │     │                    │   │
│  │  RSA pubkey  │     │  [bootloader enc]  │   │
│  │  digest      │     │  [partition enc]   │   │
│  │  DIS_JTAG    │     │  [app enc]         │   │
│  └──────────────┘     └────────────────────┘   │
│                              │                  │
│                         HW decrypt              │
│                         (on-the-fly)            │
│                              │                  │
│                           ┌──▼──┐               │
│                           │ CPU │               │
│                           └─────┘               │
└─────────────────────────────────────────────────┘
```

## Конфігурація ESP-IDF для реалізації такого захисту

```cmake
# sdkconfig options для увімкнення захисту
CONFIG_SECURE_FLASH_ENC_ENABLED=y
CONFIG_SECURE_FLASH_ENCRYPTION_MODE_RELEASE=y
CONFIG_SECURE_BOOT=y
CONFIG_SECURE_BOOT_V2_ENABLED=y
CONFIG_SECURE_BOOT_SIGNING_KEY="secure_boot_signing_key.pem"
CONFIG_SECURE_BOOT_BUILD_SIGNED_BINARIES=y
CONFIG_SECURE_BOOT_INSECURE=n

# Вимкнення JTAG та UART download mode
CONFIG_SECURE_DISABLE_ROM_DL_MODE=y
```

### Команди esptool для перевірки стану пристрою

```bash
# Переглянути стан eFuse (що заблоковано)
esptool.py --chip esp32c3 efuse_summary

# Спробувати зчитати флеш (отримаєш зашифровані дані)
esptool.py --chip esp32c3 read_flash 0x0 0x400000 flash_dump.bin

# Перевірити, чи увімкнено flash encryption
esptool.py --chip esp32c3 get_security_info
```

## Висновок

Прошивка **KrutkoC3_1.6.bin** захищена стандартним механізмом ESP32-C3
**Flash Encryption + Secure Boot**. Ключ шифрування:
- Унікальний для кожного чипа
- Фізично недоступний для зчитування ззовні
- Ніколи не передається по інтерфейсах

Це стандартна і правомірна практика захисту комерційної прошивки від
несанкціонованого копіювання та модифікації.
